Four ideas, from ring 0 to the chat box

Most "AI operating systems" are a chat window with file access. This one is built on a kernel whose ideas the desktop repeats at its own level, so the same rules hold in the boot sector and in the conversation.

Authority expires

In the kernel, every capability carries a Kaalka seal with a time window. On the desktop, every permission an agent holds is a lease with a deadline. There is no "allow forever" button, so a forgotten grant stops working by itself.

The system is a hash

Every kernel object is a node in a Merkle DAG and the machine has one root. Every file and setting on the desktop is a node too, and the OS has one root you can snapshot, diff and attest. Timestamps are out, so two machines with the same content agree. Keys are never in it.

Agents are processes

Inference in the kernel is a scheduling class with admission control and a budget. An agent on the desktop has a state, a token budget, a row in the process table, and a kill button. Killing it revokes its leases.

Nothing is forgotten

The kernel records events in causal order for deterministic replay. The desktop writes every tool call to a ledger, and every file change names the call that caused it. Undo restores the files and is itself an entry. History is never deleted.

The kernel is real, and it is on the desk

The RESENTMENT kernel is a from-scratch, capability-secure, AI-native kernel for x86_64, ARM64 and RISC-V: a transformer forward pass on its own operators, a SHE shell where programs start with no permissions, and a Merkle root for the whole machine. 1440 host assertions, six QEMU targets, seven self-tests on every boot.

It has a serial console and no network stack yet, so the desktop reaches it through a small bridge that relays the serial line over a WebSocket. Attach, and the Kernel window is a live console into ring 0, the Digest window shows the machine's root beside the desktop's, and the agent gets a kernel_eval tool gated by the kernel's own grants.

The desktop running inside the kernelnot yet — the kernel needs a network stack and a compositor first; both are on its roadmap

Today the desktop runs in a browser on a host and drives the kernel. The direction is for the desktop to run on the kernel, and every choice here — no server, no build step, no ambient authority, one hash — is made so that move is a port and not a rewrite. The roadmap says what comes next and what will not.
